# Root broker working notes

- The authoritative design is `../docs/tv-authd-plan.md`. M0–M3 are complete and validated. M4 hardening is deployed on top of the live toast branch; package upgrade/reinstall, memory pressure, boot-input, and log-permission checks passed. The manager-refresh UI is installed with the Apps2Samsung Partner certificate. The M4 cold boot passed on 2026-11-08; no M4 acceptance items remain.
- A separate track, `../docs/tv-authd-pkg-install-plan.md`, covers package installation. Its M1–M4 daemon/UI work is TV-validated for TPK installs, uninstalls, `pkg.list`, the prompt-free uid-0 root role, on-device re-signing, and Samsung Home registration (via `wascmd` under `unshare -m`). WGT installation is blocked by this firmware (`-4 Load archive info fail`) for every backend.
- Do not commit or otherwise mutate Git history unless the user explicitly asks.
- The TV is on and Vetro is active. The live package broker is the M4 binary `36ed2cdc…`; `/opt/tv-auth/grants.json` is v2 with a Vetro fingerprint and `notify: first`; `/run/tv-auth` is `0711` and the log is `0600`. No test packages remain and the probe's stale Home row was removed. The live UI is signed with the Apps2Samsung Partner certificate (TPK SHA-256 `20358bf4…`). Use the Partner profile for UI updates. Do not restart `tv-authd` (or stop the M4 service), change grants, install packages, run memory pressure, or reboot without explicit coordination.
- `pkg.install`/`pkg.uninstall` go through `wascmd` under `unshare -m` with `/run/tv-auth/etc-norelease` (a symlink farm for `/etc` without `release`) and `/run/tv-auth/etc-real`; `--no-was` selects `pkgcmd`. Do not delete those directories by hand; the daemon rebuilds the symlink list before every package operation and at startup.
- The trust directory holds two root CAs: `author-root-ca.pem` (tizen-developer) and `user-root-ca.pem` (tizen-public/partner), plus the four M3 signing files. Tizen rejects a distributor chain whose root is also in `tizen-developer`.
- Unsigned ELFs cannot execute from the VDFS in `/opt`; run `tvauth-cli` (and test binaries) from a copy under `/run`. Root-shell tools like `node` are also gated by UEP; use `test-clients/rootcli` for the root role.
- Keep each spike self-contained under its assigned `spikes/<name>/` directory. Do not edit another spike's files or shared build files while agents work in parallel.
- Prefer synchronous/blocking Rust and small, focused crates. Do not introduce Tokio or another async runtime. Pragmatic crates are allowed when they avoid reinventing nontrivial code.
- Daemon-side artifacts target `armv7-unknown-linux-musleabihf`. The approval UI is a managed `netcoreapp3.1` Tizen .NET TPK. Do not package a custom native ELF UI: the M0 spike proved UEP prevents launchpad from executing unsigned native binaries from writable app storage, even with a correctly signed TPK.
- Run host-side builds/tests when possible. Record exact commands, toolchain versions, artifact sizes, and results in the spike README.
- Clearly distinguish host validation, emulation, cross-compilation, and actual TV validation. Never claim an on-TV result that was not observed.
- Build products belong in each spike's `target/` or `out/` directory and must not be committed.
