# Root broker working notes

- The authoritative design is `../docs/tv-authd-plan.md`. M0–M3 are complete and validated. M4 hardening is deployed on top of the live toast branch; package upgrade/reinstall, memory pressure, boot-input, and log-permission checks passed. The approval UI was migrated to the native Rust/EFL `type="capp"` build on 2026-11-08 and passed the full prompt/package/toast/manager plus cold-boot acceptance run. The previous managed `.NET` UI remains available as a rollback artifact.
- A separate track, `../docs/tv-authd-pkg-install-plan.md`, covers package installation. Its M1–M4 daemon/UI work is TV-validated for TPK installs, uninstalls, `pkg.list`, the prompt-free uid-0 root role, on-device re-signing, and Samsung Home registration (via `wascmd` under `unshare -m`). WGT installation was reported blocked (`-4 Load archive info fail`) on 2026-11-08, but on 2026-11-09 minimal WGTs installed (re-signed, WAS backend, Home row), launched, and uninstalled; the old failure did not reproduce.
- Do not commit or otherwise mutate Git history unless the user explicitly asks.
- The TV is on and Vetro is active. The live package broker is the Phase 2 build (deployed 2026-11-09; it never launches a UI). Backups: Phase 1 `33ef31ee…` at `/opt/tv-auth/tv-authd.phase1-20261109`, the pre-workspace native-UI daemon at `/opt/tv-auth/tv-authd.pre-workspace-20261109`, the M4 binary at `/opt/tv-auth/tv-authd.m4-20261108`. Prompts and toasts come from `tv-auth-popupd` (`/opt/tv-auth/tv-auth-popupd`, unit `/opt/tv-units/tv-auth-popupd.service`, log `/tmp/tvauth-popupd.log`); stop that unit to fall back to `ui_unavailable` denials, not to the old UI; `/opt/tv-auth/grants.json` is v2 with only the Vetro fingerprint and `notify: first`; `/run/tv-auth` is `0711` and the log is `0600`. No test packages remain. The live `org.tvauth.ui` is the manager-only Rust build (installed TPK SHA-256 `49a40bdb…`), staged through `/run/tv-auth/ui-bin/tv-auth-ui`. Do not restart `tv-authd`, change grants, install packages, run memory pressure, or reboot without explicit coordination.
- `pkg.install`/`pkg.uninstall` go through `wascmd` under `unshare -m` with `/run/tv-auth/etc-norelease` (a symlink farm for `/etc` without `release`) and `/run/tv-auth/etc-real`; `--no-was` selects `pkgcmd`. Do not delete those directories by hand; the daemon rebuilds the symlink list before every package operation and at startup.
- The trust directory holds two root CAs: `author-root-ca.pem` (tizen-developer) and `user-root-ca.pem` (tizen-public/partner), plus the four M3 signing files. Tizen rejects a distributor chain whose root is also in `tizen-developer`.
- Unsigned ELFs cannot execute from the VDFS in `/opt`; run `tvauth-cli` (and test binaries) from a copy under `/run`. Root-shell tools like `node` are also gated by UEP; use `tvauth-cli` (`../bins/tv-auth-cli`) for the root role.
- Keep each spike self-contained under its assigned `spikes/<name>/` directory. Do not edit another spike's files or shared build files while agents work in parallel.
- Prefer synchronous/blocking Rust and small, focused crates. Do not introduce Tokio or another async runtime. Pragmatic crates are allowed when they avoid reinventing nontrivial code.
- Daemon-side artifacts target `armv7-unknown-linux-musleabihf`. The approval UI is the native `type="capp"` Rust/EFL TPK in `../bins/tv-auth-ui`, built for `armv7-unknown-linux-gnueabi`. UEP still blocks an ELF whose `d_path()` starts with `/opt`, so `../bins/tv-authd/src/ui_alias.rs` bind-mounts the installed binary at `/run/tv-auth/ui-bin/tv-auth-ui` and replaces `bin/tv-auth-ui` with a symlink to it. The 2026-11-08 spike and live migration validated the mapping, SMACK label, prompts, toasts, manager, and cold boot. The managed `.NET` implementation was removed from the tree after acceptance; it remains at git commit `7b39883` if a source rollback is ever needed.
- Production crates live in the root Cargo workspace (`../bins/*`, `../crates/*`); build them for the TV with `../cross-build.sh` (via each bin's build script). Spikes are excluded from the workspace and keep their own lockfiles.
- Run host-side builds/tests when possible. Record exact commands, toolchain versions, artifact sizes, and results in the spike README.
- Clearly distinguish host validation, emulation, cross-compilation, and actual TV validation. Never claim an on-TV result that was not observed.
- Build products belong in each spike's `target/` or `out/` directory and must not be committed.
